# 设计说明书

## 1. 目录与组件

- `src/app/bdpan`：FastAPI、百度网盘客户端、SQLite、同步与后台任务。
- `src/app/frontend`：Vue 3 + Vite 源码。
- `src/app/frontend/public`：浏览器标签页图标（favicon.svg/favicon.ico）等静态资源，
  构建时由 Vite 原样拷贝到 `web_static`。
- `src/app/bdpan/web_static`：Vue 构建产物。FastAPI 中 `/` 返回 index.html，
  `/assets` 与 `/favicon.ico`、`/favicon.svg` 直接提供静态文件。
- `config/app.json`：非敏感运行配置，可由系统配置页和任务中心原子更新。
- `data/app.sqlite3`：业务数据库，同时保存用户密码哈希与页面权限。
- `data/secrets.json`：自动生成的会话密钥和按 Cookie ID 保存的百度 Cookie 原文。
- `logs`：轮转日志、PID 与进程输出。
- `src/JenkinsConfig`：Jenkins Pipeline 定义。

## 2. 认证与授权

用户、密码哈希、角色和页面权限全部保存在 SQLite。密码使用带随机盐的 scrypt 哈希，
系统运行期间不读写明文密码文件。首次启动且数据库没有用户时自动创建
`admin / admin123`；启动和权限变更时保证至少存在一个可用管理员。

浏览器保存签名、HttpOnly、SameSite=Lax 会话 Cookie。每个受保护 API 根据当前用户
角色和 `user_page_permissions` 表执行授权。任意已登录用户可通过
`POST /api/account/password` 校验当前密码后修改自己的密码；管理员通过用户管理
接口新增用户或重置密码，不再同步 `password.txt`。

升级迁移：若存在旧版 `data/password.txt`，启动时一次性导入数据库中尚未存在的用户，
已存在用户名保持数据库中的密码和角色，随后删除明文文件。旧文件不存在或数据库为空
时只执行默认管理员初始化。

## 2.1 运行配置管理

`AppConfig` 在内存中保存当前运行配置，并记录配置文件路径和旧版账号文件路径。
`GET /api/settings` 返回 `config.editable`、`config.readonly` 和
`restart_required`：系统名称、日志保留、任务并发、调度轮询和同步历史策略可在页面
维护；监听地址、端口、时区、数据库和日志路径只读展示。

`PUT /api/settings` 仅管理员可用。接口校验字段和范围后，通过临时文件加
`os.replace` 原子写回 `config/app.json`，再更新内存配置。日志保留天数写入
`TimedRotatingFileHandler.backupCount`；调度轮询、同步历史保留和每映射最大运行数
直接更新 `TaskManager` 运行参数；`task_workers` 因线程池在启动时创建，写回配置后
提示重启生效。系统配置页负责基础设置与账号安全，任务中心负责任务与历史设置。

## 3. 后台任务

耗时的分享索引和同步任务在线程池执行。调度线程按配置间隔扫描启用自动同步的映射，
同一映射禁止并发执行。同步历史写入 `sync_runs`。进程内任务通过 `run_id` 关联持久化
同步运行，状态接口仅把 `queued`、`running` 任务作为当前任务返回；结束状态由同步历史
承载。

`sync_mappings` 记录 `last_attempted`、`retry_after` 和 `consecutive_failures`。
调度条件同时要求正常同步周期到期且当前时间不早于 `retry_after`。普通错误从 5 分钟
开始指数退避，最大 6 小时；百度 `errno=-65` 从 6 小时开始，最大 24 小时。成功同步
更新 `last_synced` 并清空退避，因而应用重启后也不会丢失失败节流状态。

同步成功后，任务编排层将 `SyncResult.files_added` 和 `files_updated` 批量写入
`sync_file_events`，保存映射、运行、相对路径、文件名、动作和同步时间。失败、跳过和
删除文件不写入成功事件。

每次同步结束后清理已完成历史：默认保留 90 天，且每个映射最多保留 200 次运行。
`sync_file_events` 通过外键随运行记录级联删除；进程内完成任务也只保留最近 200 条。

每条分享链接通过 `cookie_id` 关联 Cookie 元数据。分享索引、刷新和同步任务统一按
链接解析 Cookie，任务开始时读取秘密形成快照；客户端产生的新 Cookie 字段只写回原 ID。

## 4. 存储安全

Windows SMB 使用 UNC 或远程驱动器；Linux/macOS 要求路径位于真实挂载点之下。
每次同步前验证现存父目录和写权限，再使用同目录临时文件下载、校验大小和原子替换。

文件版本元数据保存在文件所在目录的
`.bdpan_meta/<sha256(原文件名 UTF-8)>.json`，元数据名固定长度，不会因给接近
`NAME_MAX` 的原文件追加后缀而触发 `ENAMETOOLONG`。读取顺序为新哈希格式、旧
`原文件名.bdpan`；探测旧格式发生路径错误时视为不存在。新元数据用固定长度临时名写入
后原子替换，成功后清理可访问的旧旁车。

## 5. 数据迁移

首次使用新结构且 `data/app.sqlite3` 不存在时，可复制旧默认数据库。数据库启动时通过
幂等建表和 `ALTER TABLE` 增加新字段，保留分享、索引和同步映射。

本次迁移为 `sync_mappings` 幂等增加失败调度字段，旧记录默认无退避，不改变既有
`last_synced` 和自动同步配置。

`sync_file_events` 使用幂等建表及索引创建完成升级。按运行查询返回该次事件；按映射
查询通过相关子查询为每个相对路径选择最新事件。旧同步运行不回填数据。

`baidu_cookies` 保存名称、脱敏摘要、三态有效性、添加/更新时间和最近校验信息。
启动时把旧 `secrets.json.cookie` 移入 `cookies.<id>`，创建“默认 Cookie”并只为尚未
关联的旧分享补齐 ID，因此可重复执行。`BDPAN_COOKIE` 映射为只读 ID 0，不落盘。

## 6. Cookie API、安全与校验

- Cookie 元数据读取需要系统配置页权限；新增、编辑、删除和校验仅管理员可用。
- 名称按大小写不敏感唯一，原文用临时文件加 `os.replace` 原子替换；被引用时删除返回
  409。浏览器响应、任务消息和日志不包含原文。
- 校验成功标记 `valid`，明确无效登录标记 `invalid`；网络、超时和百度风控只记录脱敏
  错误并保留原状态。页面按 `Asia/Shanghai` 显示时间。

## 7. 同步文件接口与界面

- `GET /api/mappings/{mapping_id}/files`：需要同步映射页面权限，返回映射文件最新记录。
- `GET /api/sync-runs/{run_id}/files`：需要任务中心页面权限，返回单次同步运行文件。
- 两个接口只接受 `file_name`、`synced_at` 排序字段及 `asc`、`desc` 方向，SQL 使用固定
  白名单片段，并以相对路径作为稳定次级排序。
- 返回相对路径、文件名、动作和时间等界面所需元数据，不返回本地绝对路径。
- Vue 使用一个共享弹窗承载映射、当前同步任务和同步历史入口，并处理加载、错误、空
  记录和排序状态；时间统一按 `Asia/Shanghai` 显示。


## 多网盘支持（2026-10-25）

- 支持百度网盘、夸克网盘分享的添加、提取码识别、目录索引与浏览、刷新、同步和定时任务。
- FastAPI、Vue、SQLite 及现有登录、权限、任务中心、同步策略保持兼容；包名、CLI 命令、服务名称和访问地址沿用原值。
- 分享记录与 Cookie 元数据增加 `provider`（`baidu` / `quark`）。启动时自动补充数据库字段，历史记录默认为百度网盘，无需手工迁移。
- 在系统配置页添加 Cookie 时选择网盘类型：百度需要 `BDUSS`，夸克需要 `__puus`。Cookie 原文继续仅存于服务端 secrets.json；分享与凭据类型必须一致，已建分享不可直接切换网盘类型。
- 添加分享时可直接粘贴 `https://pan.quark.cn/s/分享ID?pwd=提取码` 或带中文提取码的文本，选择同网盘凭据。
- 夸克下载先将文件转存到所选账号的根目录，再获取下载地址。转存文件保留、占用网盘容量；再次同步更新文件可能产生额外转存。容量不足或接口拒绝时任务失败并保留错误日志。
- 夸克 API 使用 Web 接口，可能随平台更新或风控失效。可通过环境变量 `QUARK_API_URL` 覆盖 API 基址（默认 `https://drive-pc.quark.cn/1/clouddrive`）。需要有效账号 Cookie；模拟接口测试不能代替真实账号验收。
- CLI 同样按分享类型分派客户端；例如 `bdpan config --provider quark --name 夸克账号 --cookie '完整Cookie'`，添加分享时可用 `--cookie-id` 指定凭据。
- Jenkins 增量更新排除 `config/app.json`，仅首次部署复制默认配置，保留线上 data、日志与配置。升级前建议备份 SQLite、secrets.json 和配置文件。

适配实现位于 `providers.py` 与 `quark.py`，沿用百度客户端的解析、准备下载和下载接口。夸克文件 ID 加 `quark_` 前缀存入现有 SQLite 字段，避免全数字长 ID 被 INTEGER 亲和性转换后丢失精度。目录请求失败或超出递归深度时终止索引，避免残缺索引用于同步。

## 分享链接状态判定（2026-11-03）

- `providers.is_share_invalid_error()` 统一识别可确认失效的异常：百度分享校验返回的
  `-7`、`-8`，带 `share_invalid` 标记的失效分享页以及 `-21`；夸克 `41004`、`41006`、
  `41011`、`41012`、`41019` 和受限码 `41010`、`41031`。
- 刷新和同步在准备分享会话阶段捕获上述异常，使用独立数据库连接把对应分享状态改为
  `invalid` 并更新 `last_checked`；网络错误、提取码错误、限流、风控和未知错误码保持原状态。
- 同步成功准备分享会话后把状态恢复为 `active`，因此链接重新有效时无需手工改库。
- 前端把 `active`、`invalid`、`unknown` 等状态显示为中文标签；超过 30 天未成功检测的
  `active` 链接显示为“待检测”，避免长期展示已经过时的“有效”结论。

Linux 运维脚本会优先管理已安装的 systemd 单元（环境变量 `BDPAN_SYSTEMD_UNIT`，默认 `baidupan.service`），否则使用原 PID 模式。Jenkins 用户需获准以 sudo 无密码执行对应单元的 start/stop；本次部署已添加仅限该单元启停的规则。

## 账号与配置界面维护（2026-11-07）

- `auth.py` 只保留密码哈希、默认管理员初始化、旧文件一次性迁移和用户载荷；日常
  登录与用户管理不再读写账号文件。启动时先合并旧版 `data/password.txt` 中数据库
  缺少的用户，再确保存在可用管理员，最后删除明文文件。
- `config.py` 的 `AppConfig` 持有当前配置、配置文件路径和旧版账号文件路径；
  `settings_payload()` 把配置分为 `editable`、`readonly` 和 `restart_required`。
- `PUT /api/settings` 校验字段与取值范围，原子写回 `config/app.json` 并更新内存配置；
  日志保留更新轮转处理器，调度与历史参数更新 `TaskManager`，任务并发数提示重启。
- 前端系统配置页提供基础设置、账号安全、部署信息和 Cookie 四个区域；任务中心为
  管理员提供任务设置弹窗。左下角账号区增加修改密码入口，移动端也保留该入口。
- 新增数据流：`POST /api/account/password` 校验当前密码后更新当前用户的 scrypt 哈希；
  用户新增、编辑、删除全部直接操作 SQLite。
